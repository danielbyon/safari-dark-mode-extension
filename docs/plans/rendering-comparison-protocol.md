# Preliminary rendering comparison protocol

Use this protocol to find out which Safari capabilities are available and how a rendering candidate behaves under the same conditions as Dark Reader and Noir. The fixtures below are specifications for a later disposable probe. All Safari runs, competitor comparisons, accessibility observations and resource measurements are **`NOT_RUN`**. The [candidate audit](rendering-candidate-audit.md) records the inspected package and the source evidence behind these questions.

## 1. Deterministic fixture specifications

Use local, versioned content, owned or cleared media and synthetic input. Serve distinct origins where specified. Record fixture revision and media hashes. Each action must have an explicit completion signal, such as an inserted node, a completed route change or the target video frame. Preserve an extension-off reference after the same actions. Use that reference to distinguish lost site state from a change the website legitimately made.

| Fixture | Actions in order | What to capture |
|---|---|---|
| Article, controls and media | Cold-load an article with a branded header, custom links, a form, semantic error/success, focused/disabled/selected controls, SVG and canvas chart series. Include a photograph, screenshot and artwork, a CSS background using the same content image, an interface icon/sprite, and a local video paused on a known frame. Compare adaptive appearance and each built-in palette. Vary background, text, link, brightness, contrast, saturation and warmth one field at a time. Toggle independent image dimming off/on/off. Disable after entering synthetic text. | First visible frame, settled color samples, visible focus, control state, chart legend/series correspondence, same image regions and video frame. Verify preserved media at default, dimming only classified content when enabled, changes to the targeted field, retained input and restored page. Record ambiguous CSS backgrounds as unclassified. |
| Dynamic application | After first paint insert a styled component, replace a linked sheet, change a CSS variable and inline style, mutate a CSSOM rule, update an open shadow root/adopted sheet and change SVG fill/stroke. Repeat the same ordered burst while toggling. Change the site-authored theme-color metadata on a same-host SPA route before a delayed update completes, then disable. | Before/after values for each element, missed or stale updates, DOM-only preview retention, navigation invalidation, and cleanup. Compare the restored meta content with the site's latest value on the extension-off route. Check input and focus as well. Record inaccessible shadow content separately. |
| Website-controlled native dark mode | Start a light page with a dark hero. Enable adaptive darkening, then trigger three detector reevaluations without changing site appearance. Repeat with a custom palette. Have the site switch to its own dark stylesheet, then back to light while eligible. Include an initially dark page and a site theme signaled by CSS alone. Exercise Use My Theme with effective activation On and Off. In a WP Dark Mode variant, set its preset marker, enable and disable the candidate, then activate the site theme in the same document and allow the mutation observer to run. | Log site-owned state, effective activation, renderer state, detection reason and each transition. The dark hero and the extension's output must not count as native dark. Preserve genuine native dark when required. Use My Theme alone cannot activate a saved-Off page. Check that the site-owned WP active class and attribute survive after disable and the page matches the site-dark control. Count false positives/negatives and unexpected enable/disable cycles. |
| Frames and stylesheet access | Put same-origin and cross-origin documents, including a nested frame, on a controlled top-level page. Give the frame host a conflicting saved rule. Vary its grant and native appearance independently. Inside an authorized document load a same-origin stylesheet, a CORS-readable foreign sheet, and an applied sheet with unreadable CSSOM. Vary the resource origin's host grant separately from the document's grant. Exercise nested cross-origin `@import`, redirect to an ungranted origin, load failure and grant revocation while a read is pending. | Record frame tree, grants per origin, CORS headers, CSSOM-read result, resource request/response or rejection, final computed style, and remaining site functionality. Separate browser loading the site's original sheet from any extension-initiated read. Only authorized frames inherit top-level effective values. Check native-dark preservation per frame. Distinguish rejection before the public fetch hook, denial by the permission-aware loader, and a failed browser read. A rejected read must leave the original sheet usable and must not widen access. Record incomplete darkening and actionable recovery if immediate restoration is impossible. |
| Eligible preview and compatibility fix | Prepare a saved-Off or native-dark page where transforming one element breaks an essential control. Specify a bundled, versioned fix scoped to that element. Start an explicit preview with valid access, permission and pause off. Repeat with denied permission, unavailable purchase access, and Pause Everywhere, separately. Edit at a broader scope with a narrower override, preview Use Default at its owning scope, and change saved settings during preview. | Eligible preview receives the fix. Each ineligible case leaves the page untouched. Ordinary DOM mutation retains the draft. Dismiss, reload, open a new top-level document, or change top-level URL by path, query, fragment or SPA route: each discards the draft and resolves the latest saved state. Verify the fix never changes a saved choice or silently raises deliberate low contrast. |

**Cross-origin positive control.** Use an authorized document and a controlled HTTPS stylesheet origin on the default port. The candidate's origin guard must accept the resource independently of Safari's grant. Set identical response headers in both runs: the site can apply the original sheet, but ordinary page CSSOM and fetch cannot read its contents. Confirm that prerequisite with extension-off. In two fresh documents keep the URL, CORS headers, document grant, candidate and loader identical. Change only the Safari grant for the resource origin. In both runs verify the public hook is reached and record the resource grant seen by the loader. With the grant present, require a successful authorized read and transformation of a distinctive rule. With the grant denied, require refusal before a privileged read, no extension-initiated resource request, and preservation of the original sheet. This pair measures end-to-end behavior under a changed grant. When the loader refuses the read, label the outcome loader-enforced and leave Safari's transport-level denial unobserved. The separate candidate-guard control uses a local resource origin rejected before the hook and measures only that guard. Distinguish site requests from extension requests in each trace. If a controlled origin or independently variable resource grant is unavailable, record the affected path as `NOT_RUN` and explain the platform limitation. Keep the candidate guard intact. [Upstream resource checks](https://github.com/darkreader/darkreader/blob/16315ce11428af9350d8924cea09c4066725709d/src/utils/network.ts#L122-L145)

**Appearance and recovery check.** Record the owning scope of the theme and each relevant override. Test normal text, large text, controls, focus and non-color state cues against applicable WCAG 2.2 AA criteria with an unmodified built-in theme, including adaptive output. Then deliberately save low-contrast colors. Verify the warning permits the choice and guided recovery identifies which overrides must be explicitly removed, explains broader effects and remains operable. Select a built-in theme with both page and domain link-color overrides. Remove the page override and verify that recovery identifies the revealed domain value and its owning scope. Explain the wider effect, explicitly remove the domain override, and resolve again. Report unmodified built-in appearance only when all applicable overrides have been removed and the effective values match the built-in reference. Attribute the contrast directly caused by the chosen values to that choice. Lost focus, inaccessible recovery, hidden controls or altered video remain separate product failures. Record existing website defects against extension-off. [Appearance requirements](../adr/0007-first-release-appearance-controls.md) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 2. Three public website cases

Run logged out, in the specified language and without personal browsing data. Record the exact final URL, revision when available, date, consent state and visible page landmark. A changed website earns a recorded deviation. If equivalent states cannot be recovered, mark the affected comparison `NOT_RUN` and retain the reason.

1. **Wikipedia, Color vision.** Use the English article at a recorded permanent revision. Capture its lead and one identified illustration with its caption, follow a section anchor and return. Record the website's appearance setting. This exercises reading, linked text, illustrations and navigation. [Article](https://en.wikipedia.org/wiki/Color_vision)
2. **MDN, HTML input element.** Open the English reference, record the site appearance, navigate to the input types table and exercise a keyboard-focusable control. Compare the same location with the site's light and dark choices where available. Record the selected control and route. [Input reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input)
3. **OpenStreetMap, central London.** Open the Standard map layer at zoom 15 and coordinates 51.5074, −0.1278. Wait for the same visible tiles, zoom in once, open and dismiss the layer selector, and return to the initial view. Record map center, zoom, layer and any missing tile. This exercises dynamic controls, imagery and meaningful map colors. [Starting view](https://www.openstreetmap.org/#map=15/51.5074/-0.1278)

## 3. Comparable runs and measurements

1. **Identify the environment.** Record run date, operator, device/model, physical or simulated, OS and Safari version/build, browser tab or supported Add to Dock app, viewport in CSS pixels, scale, orientation, zoom, system and site appearance. Include locale, power/thermal state, instrumentation and any unavailable counters. Compare within a device and OS combination. Document Private Browsing separately where relevant.
2. **Set four conditions.** Use extension-off, commercial Dark Reader for Safari, Noir and the exact candidate revision/build. Enable one renderer at a time and reset to the same starting page and stored state. Record comparator app and extension versions, selected theme/method, defaults, site-specific settings, system appearance and all grants. Start with ordinary darkening at defaults, then match settings where the products expose comparable controls. Mark unsupported controls as such. For an unavailable comparator, platform, instrument, or candidate use `NOT_RUN` with the reason. Never count that cell in a score. [Dark Reader for Safari](https://darkreader.org/safari/) · [Noir](https://getnoir.app/)
3. **Keep page and network state comparable.** Record fixture/site identity, expected state, input, scroll position, focus, frame and resource origins, cache condition, connection profile, and site data reset. Use a fresh page/cache for cold loads and the same primed cache for warm repeats. Log any differences caused by a live site or a comparator. Preserve only sanitized measurements and cropped public or synthetic evidence.
4. **Use a fixed exploratory schedule.** For each condition record one cold load and three warm repetitions from the same starting state. Rotate the starting condition across repetitions. Use a timestamped screen recording from before navigation through settled appearance. Mark navigation start in the recording. Measure any bright blank interval before first content separately, then measure first content to first correct appearance. For fixtures use fixed surface and text swatches with recorded expected colors and a visible page-state marker. Record frame numbers, milliseconds, capture rate, and uncertainty. Compare pre-content frames with extension-off to attribute a browser transition. A correctly dark first content frame can still follow a bright blank interval. For restoration, time disable/discard to the first restored frame and verify settled state against extension-off. If frame capture cannot resolve a flash, record the measurement limit.
5. **Measure active and idle costs.** On the dynamic fixture replay 30 identical mutation batches, one per second. Record baseline, 30 seconds of activity, 30 seconds of idle and 30 seconds after disable. Measure input-to-visible-response at the same action, peak and settled memory in MiB, and CPU over each window. Name the instrument, counter, process or aggregation boundary, units and sampling interval. Separate WebContent, extension and shared-browser totals where available. Record raw samples and warm median/range. Incomparable process attribution or instrumentation stays explicit. These windows define observation, not a performance target.
6. **Classify outcomes by impact.** Record expected/actual behavior, baseline, repeatability, affected role or region, method, evidence and severity for each condition. *Critical* covers unreadable primary content, lost input, broken essential controls or rendering across a denied permission boundary. *Major* impairs an important task or materially changes meaningful media. *Minor* is localized cosmetic breakage with the task intact. Record other resource and flash findings with magnitude, duration and user impact. Preserve isolated critical failures in the summary. Do not average them away.
7. **Keep one row per condition and scenario.** Include environment and settings reference, fixture revision or live page state, repetition, expected result, observed result or `NOT_RUN` reason, measurements, severity, attribution and evidence location. Distinguish observed behavior from a proposed explanation. For stage-specific measurements outside a probe's remit, leave the observation `NOT_RUN`. Repeat only the affected rows when instrumentation, settings, source or page state changes.

## 4. Questions the next investigations must settle

| Investigation | Evidence required before its decision |
|---|---|
| **Safari capability and lifecycle** | Supply per-platform SDK/API availability and observed supported, limited, unavailable or `NOT_RUN` results for injection timing, CSP/script worlds, permission and access precedence, frame/resource grants, revocation and recovery. In the proposed execution world, record an ordinary host message and expected reply before loading the bundle, after import and after disable, including the return value and whether the reply arrives. Test popup dismissal, suspension/wakeup, tab identity, navigation and preview disposal against the latest saved state. Include same-host tab-override survival, cross-host expiry, duplicate/restored tabs, persistent pause, schedule boundaries/DST, macOS shortcut conflicts, Private Browsing and supported Add to Dock contexts. Keep optional conveniences separate from mandatory OS constraints. [Issue #3](https://github.com/danielbyon/safari-dark-mode-extension/issues/3) |
| **Empirical rendering comparison** | Use the qualified Safari probe to measure the matrix against identical fixture and site states. For each gap identify a public-API adapter, required engine modification, or reproducible failure that warrants a static/filter alternative. Show which fixes must be reapplied after an upstream update. Recommend reuse, modification or replacement with evidence. Escalate a substantial fork or unmet mandatory behavior to the owner. [Issue #4](https://github.com/danielbyon/safari-dark-mode-extension/issues/4) |
| **Release qualification method** | Extend the preliminary cases with Safari, rendering and native-boundary findings. Obtain owner approval of the final 30–50-site corpus, devices, metrics, thresholds and coverage before final qualification. Maintain three separate gates for critical regressions, competitive rendering/resource quality and scoped customization/inheritance/usability. Exploratory measurements cannot establish release readiness. [Issue #8](https://github.com/danielbyon/safari-dark-mode-extension/issues/8) |
